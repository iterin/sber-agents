## Отчёт по заданию модуля 6

### 1. Проект

- **Название проекта**: RAG‑ассистент Сбербанка (модуль 6 «Мониторинг и оценка качества RAG‑систем»)
- **Краткое описание**: Telegram‑бот, который отвечает на вопросы пользователей по документам Сбербанка (PDF и JSON‑FAQ) с помощью RAG‑подхода на базе LangChain, ведёт историю диалога, отображает источники и поддерживает автоматическую оценку качества через RAGAS и LangSmith.
- **Вариант задания**: **базовый**

### 2. Используемые модели и провайдеры

- **RAG (онлайн‑ответы бота)**  
  - **Провайдер LLM**: Fireworks (`OPENAI_BASE_URL=https://api.fireworks.ai/inference/v1`)  
  - **Основная модель генерации**: `MODEL=accounts/fireworks/models/gpt-oss-120b`  
  - **Модель для query transformation**: `MODEL_QUERY_TRANSFORM=accounts/fireworks/models/gpt-oss-120b`  
  - **Модель эмбеддингов для индексации**: локальная `models/multilingual-e5-base` (через `HuggingFaceEmbeddings`), использование принудительно включено флагом `USE_LOCAL_EMBEDDING=True` в `config.py`.

- **RAGAS evaluation (оценка качества)**  
  - В проекте для RAGAS используются отдельные параметры `RAGAS_LLM_MODEL` и `RAGAS_EMBEDDING_MODEL`. В `config.py` заданы значения по умолчанию:  
    - `RAGAS_LLM_MODEL="gpt-4o"`  
    - `RAGAS_EMBEDDING_MODEL="text-embedding-3-large"`  
  - Явных переопределений этих переменных в `.env` нет, поэтому при запуске evaluation используются именно эти значения по умолчанию.

### 3. Создание и загрузка датасета

- **Подход к созданию датасета**  
  Датасет создавался **комбинированным способом** с помощью скрипта `src/dataset_synthesizer.py` и команды `make dataset`:
  - Для PDF‑документов:
    - Загружаются все PDF из директории `data/`.
    - Каждый файл разбивается на чанки (через `RecursiveCharacterTextSplitter`, `chunk_size=500`, `chunk_overlap=50`).
    - Из каждого PDF равномерно берётся по несколько чанков (`samples_per_file`), и на основе каждого чанка LLM (`ChatOpenAI`) синтезирует 1 вопрос и краткий ответ. Эти пары попадают в датасет как синтетические Q&A.
  - Для JSON‑FAQ (`sberbank_help_documents.json` и др.):
    - Скрипт `load_json_qa_pairs` выбирает случайные готовые Q&A пары.
    - В датасет добавляются записи с полями `question`, `ground_truth` (поле `answer` из JSON) и `contexts` (поле `full_text` или `answer`).
  - Сформированный датасет сохраняется в файл `datasets/06-rag-qa-dataset.json`.

- **Размер датасета**  
  - В финальной версии датасета `06-rag-qa-dataset.json` используется **8 примеров** (что подтверждается выводом `/evaluate_dataset`: `Примеров обработано: 8`).

- **Загрузка датасета в LangSmith**  
  - Для загрузки используется команда `make dataset-upload`, которая вызывает функцию `upload_to_langsmith` в `src/dataset_synthesizer.py`:
    - Создаётся датасет в LangSmith с именем из `LANGSMITH_DATASET` (в проекте — `06-rag-qa-dataset`).
    - В датасет загружаются примеры в формате `inputs={"question": ...}`, `outputs={"answer": ground_truth}` и `metadata` из локального JSON.

- **Скриншот страницы датасета в LangSmith**  
  - Скриншот с вкладки **Experiments** для датасета `06-rag-qa-dataset` расположен в репозитории по пути:  
    - [`screenshots/LangSmith.png`](screenshots/LangSmith.png)

### 4. Оценка качества через RAGAS

- **Используемые метрики** (см. `src/evaluation.py` и описание в `README.md`):
  - `Faithfulness` — **Обоснованность** (нет галлюцинаций; ответ опирается на контекст).
  - `AnswerRelevancy` — **Релевантность ответа** исходному вопросу.
  - `AnswerCorrectness` — **Правильность ответа** относительно эталонного `ground_truth`.
  - `AnswerSimilarity` — **Семантическое сходство** ответа с эталоном.
  - `ContextRecall` — **Полнота контекста** (насколько retrieved документы содержат всю нужную для ответа информацию).
  - `ContextPrecision` — **Точность поиска** (доля действительно релевантных документов среди retrieved).

- **Текущие результаты (последние запуски)**  
  - По логам последнего evaluation (см. `terminals/45.txt`):
    - `faithfulness ≈ 0.75` — уровень галлюцинаций заметно снижен после настройки промптов и уменьшения `temperature` основной модели.
    - `context_recall = 1.0` — retrieval находит необходимые документы для всех примеров датасета.
    - Для ряда запусков некоторые метрики (`answer_relevancy`, `answer_correctness`, `answer_similarity`, частично `context_precision`) давали `nan` из‑за ограничений провайдера (ошибки 402 Payment Required / rate limit при вызове LLM внутри RAGAS). Это связано не с логикой кода, а с лимитами внешнего API.

### 5. Выводы и главные инсайты о качестве RAG‑системы

1. **Retrieval стал надёжным после доработок**  
   - Переход на локальные эмбеддинги `multilingual-e5-base` существенно улучшил работу на русскоязычных документах по сравнению с удалённой моделью `qwen3-embedding-8b`.
   - Разбиение JSON‑FAQ на отдельные чанки «Вопрос: …» и «Ответ: …» и увеличение `RETRIEVER_K` позволили системе стабильно находить нужные ответы (например, про «виртуальную карту без пластика» и «дату и место получения карты»).
   - Это отражается в `ContextRecall`, который в последних измерениях достигает `1.0`.

2. **Галлюцинации удалось заметно сократить**  
   - Снижение `temperature` основной модели и уточнение системного промпта (жёсткое требование опираться на контекст и не придумывать детали) привели к росту `Faithfulness` до ~`0.75`.
   - Бот перестал «фантазировать» в ответах, когда в документах нет информации: в таких случаях он корректно сообщает, что не нашёл ответ в доступных документах.

3. **Основное узкое место — ограничение провайдера при расчёте тяжёлых метрик**  
   - Метрики `AnswerRelevancy`, `AnswerCorrectness`, `AnswerSimilarity` и частично `ContextPrecision` требуют большого числа дополнительных вызовов LLM и эмбеддингов внутри RAGAS.
   - Из‑за ограничений Fireworks/OpenRouter (ошибки 402 и rate‑limit) часть этих вызовов не доходит, и RAGAS возвращает `nan` для соответствующих столбцов. Это техническое ограничение инфраструктуры, а не логики RAG или качества датасета.

4. **Качество можно дальше улучшать точечной настройкой**  
   - Для дальнейшего повышения метрик (особенно `AnswerCorrectness` и `AnswerRelevancy`) можно:
     - Выделить отдельный retriever только по JSON‑FAQ для типовых вопросов и комбинировать его с PDF‑retriever’ом.
     - Рассмотреть использование более однородной бесплатной модели для RAGAS (или локального LLM) чтобы избежать `nan` из‑за лимитов и стабильно считать все метрики.
   - Тем не менее, уже сейчас система демонстрирует высокую полноту контекста и приемлемую обоснованность ответов на типовые пользовательские запросы по картам и кредитам.
